# FitMind Gym Routine

검색 없이 바로 운동하려고 만든 개인 루틴 웹앱입니다. 현재 기본 루틴은 주 5일 근비대 운동, 토요일 단일 컨디셔닝, 일요일 회복과 매일 지속 가능한 지방감량 활동으로 구성되어 있습니다.

## 실행 방법
GPT 운동 추천을 포함해 실행하려면 Node.js 22 이상에서 다음 명령을 사용하세요. 새 패키지 설치는 필요하지 않습니다.

```powershell
Set-Location 'F:\06_DavValult\FitMind-AI'
npm start
```

[로컬 FitMind 열기](http://127.0.0.1:8787)

기존 배포 주소나 파일로 사용하던 기록은 저장 주소가 달라 자동으로 보이지 않습니다. 기존 앱에서 `전체 데이터 백업`을 내려받고 이 주소의 `백업 복원`으로 옮기세요. 기존 데이터가 삭제된 것은 아닙니다.

기존 운동 기록·규칙 기반 생성 기능만 사용할 때는 아래 방식도 유지됩니다.

1. 배포 주소 또는 `index.html` 파일을 브라우저로 열기
2. 월-일 요일 선택 후 운동 또는 회복 활동 진행
3. `세트 완료` 버튼으로 세트 누적
4. 휴식 타이머 확인 후 다음 세트 진행
5. 운동 종료 후 `오늘 요약 저장`

## 저장 방식
- 운동 기록은 회원가입/카카오 로그인 없이 사용할 수 있습니다. GPT 추천은 별도의 기존 Codex OAuth 연결을 사용합니다.
- 운동 기록은 브라우저의 LocalStorage에만 저장됩니다.
- 같은 기기와 같은 브라우저에서 다시 열면 최근 기록과 분석을 이어서 볼 수 있습니다.
- `전체 데이터 백업`으로 JSON 파일을 내려받고 `백업 복원`으로 다른 기기에 옮길 수 있습니다.

## 포함 기능
- 루틴 순서 자동 진행 및 기구 대기 시 미완료 운동 먼저 선택
- 월·수·금 제한된 경사 걷기, 화·목·일 회복성 걷기, 하루 8,000-10,000보 기준
- 토요일 HYROX 또는 3km 인터벌 중 하나만 선택하고 일요일은 회복 또는 완전 휴식
- 월요일 가슴·어깨·삼두, 화요일 하체 전면, 수요일 등·이두, 목요일 하체 후면, 금요일 어깨·팔·상부가슴
- 수요일 3라운드와 토요일 가벼운 2라운드의 턱걸이 10회 → 딥스 10회 슈퍼세트
- 맨몸 반복이 부족하면 어시스트 머신이나 밴드를 사용하고, 한 라운드 뒤 120초 휴식
- 화요일 레그컬 → 레그익스텐션과 카프레이즈 → 케이블 크런치, 금요일 이두컬 → 삼두 푸시다운 슈퍼세트
- 각 슈퍼세트는 두 운동을 연속 수행한 뒤 정해진 휴식을 갖고 3라운드 진행
- 숄더프레스 40kg, 랫풀다운 55kg, 레그프레스 90-95kg 시험 중량 반영
- 8-12회 중심의 더블 프로그레션과 RIR 1-3 기준
- 하루 약 250-400kcal의 작은 적자와 단백질 120-140g, 2-3주간 체중 평균·허리둘레 추세 확인
- 복근운동과 별개로 복부 지방은 식사·일상 활동·전신 운동을 함께 관리한다는 안내
- 바벨/덤벨 운동은 가능한 한 머신 또는 케이블 운동으로 대체
- 아침/점심/저녁 식단 가이드와 체크 기준 패널
- 과훈련/통증/질환 관련 안전 기준 안내
- 운동 가이드 카드
  - 운동방법
  - 기구 설명
  - 공(짐볼) 대체 운동
  - 주의 포인트 / 자주 하는 실수
- 세트 완료 및 휴식 타이머
- 완주율/검색 횟수/불안도 기록
- 최근 기록 저장(LocalStorage)
- 일별/주별/월별 기록 집계
- 4주 간격 인바디 JPG/PNG 저장
- 인바디 핵심 수치(체중, 골격근량, 체지방률, 내장지방, 허리둘레) 기반 운동·식단 조정안
- 목표, 요일, 시간, 신체정보, 경험, 장소, 장비, 부상, 식단 선호를 바탕으로 주간 운동·식단 자동 생성
- 생성 결과 저장 및 다시 보기
- 생성한 계획의 요일별 변경 미리보기·실행 루틴 적용·최근 적용 복원
- 목표와 구분한 실제 세트 중량·횟수·시간·RIR 기록, 이전 값 불러오기와 지난 기록 비교
- 최근 세트/운동 완료 취소 및 오늘만 운동 대체
- 선택한 인바디 0~6개 비교와 최근 7일/28일 수행 기록을 이용한 GPT 계획 조정
- 관리자용 운동/식단 템플릿 추가·수정·삭제

## 인바디 체크 사용 방식
- JPG/PNG 이미지는 브라우저 안에서 작게 압축해 LocalStorage에 저장합니다.
- 이미지를 자동 판독하지 않습니다. 체중, 골격근량, 체지방률을 직접 입력해야 조정안이 정확해집니다.
- 최근 12개 기록만 유지하고, 저장공간 보호를 위해 오래된 이미지는 일부 제거될 수 있습니다.
- 조정안은 의료 판단이 아니라 운동·식단 기록 보조입니다.

## 규칙 기반 맞춤 생성기
- 서버 없이 브라우저 안에서 관리자가 설정한 템플릿과 안전 규칙을 조합해 생성합니다. 생성형 AI 기능은 아닙니다.
- 목표는 최대 3개까지 선택할 수 있습니다.
- 초보자는 세트 수와 강도를 낮춰 생성합니다.
- 선택한 부상 부위와 금기 태그가 맞는 운동은 생성 결과에서 제외합니다.
- 알레르기를 입력하면 특정 음식 추천 대신 원재료 확인이 필요한 안전 식단 틀을 제공합니다.
- 운동/식단 템플릿은 앱 안의 관리자 템플릿 관리에서 수정할 수 있습니다.

## GPT 운동 추천 — Codex OAuth

1. 인바디 영역에 실제 측정 수치를 입력하고 `인바디 기록 저장`을 누릅니다. 모르는 수치는 비워 두세요.
2. 맞춤 생성기에서 목표, 가능한 요일·시간, 신체정보, 운동 경험, 장소·장비와 주의사항을 입력합니다.
3. `GPT 운동 추천`의 `Codex 연결`을 누릅니다. 인증이 필요하면 `Codex 로그인`으로 기존 Codex 브라우저 로그인을 완료한 뒤 연결을 다시 확인합니다.
4. 계정에서 조회된 **GPT 모델과 추론 강도**를 선택하고 구체적인 목표를 입력합니다. `인바디 비교 · 최대 6개`에서 전송할 기록을 선택합니다. 위의 체중 입력 기준 선택은 별도이며 `선택한 인바디 체중을 위 입력에 사용`으로 중복 입력을 줄일 수 있습니다.
5. `GPT로 운동 추천받기`를 누르면 선택 모델로 요청합니다. 완료된 계획은 기존 생성 결과 영역에 표시되고 초안으로 저장됩니다.
6. `생성 결과 저장`으로 목록에 보관하고 `보기`로 다시 엽니다. 전체 데이터 백업에 모델·추론 강도·목표·사용한 인바디 수치와 결과도 함께 포함됩니다.

추론 강도는 모델별 지원 목록에 맞춰 표시합니다. 초기값은 기존 동작과 같은 낮음(low)이며 직접 보통(medium), 높음(high), 매우 높음(xhigh) 등 지원 옵션을 선택할 수 있습니다. 이전 강도를 지원하지 않는 모델로 바꾸면 다시 선택해야 합니다. 높은 강도는 대기가 길어질 수 있으며 기존 요청 시간 제한은 유지됩니다. 저장된 과거 결과에 강도 정보가 없으면 미기록으로 표시합니다.

지원 목록은 OAuth 모델 응답을 우선 사용하고, 목록에 강도 정보가 없으면 설치된 Codex의 모델 메타데이터 캐시를 참고합니다. 캐시도 없는 경우에는 확인된 모델에 공통 강도만 표시하며, 알 수 없는 모델은 기존 low로 제한합니다. 서버에서도 모델과 강도 조합을 검사합니다. 요청은 공식 [Responses 추론 설정](https://developers.openai.com/api/docs/guides/latest-model)의 `reasoning.effort`에 선택값을 전달합니다.

AI 결과는 먼저 추천 초안으로 표시됩니다. `추천을 내 루틴에 적용`에서 요일 선택 → `변경 내용 미리보기` → `확인한 루틴 적용`으로 실제 운동 화면에 연결할 수 있습니다. 기존 루틴 편집도 계속 사용할 수 있습니다.

### 추천부터 수행·재조정까지

1. **루틴 적용:** 적용할 요일의 현재/새 운동·세트·휴식·유산소를 비교한 뒤 적용합니다. 진행 중인 세션과 오늘만 대체한 운동은 당일 계획을 유지하고 다음 운동부터 새 루틴을 사용합니다. `최근 적용 전 루틴 복원`은 최근 적용 1회만 되돌립니다. 적용 후 직접 편집했다면 그 변경을 보호하기 위해 자동 복원을 막습니다.
2. **실제 기록:** 현재 운동 아래에서 실제 중량(또는 맨몸), 횟수/시간, 선택 RIR을 입력하고 `세트 완료`를 누릅니다. `실제 기록 저장`은 수행값만 저장하며 완료 개수를 올리지 않습니다. `이전 값 불러오기`와 지난 기록 표에서 비교·수정·삭제할 수 있습니다. 루틴 편집의 목표값은 별도로 유지됩니다.
3. **완료 취소·대체:** `최근 세트/운동 완료 취소`는 최근 완료 1회를 되돌리고 타이머를 일시정지합니다. 이후 실제 기록을 직접 수정·삭제하면 그 편집을 보존하기 위해 이전 취소는 무효화됩니다. `오늘만 다른 운동으로 대체`에서 이름·세트별 목표·휴식을 입력하면 주간 기본 루틴과 이미 수행한 기록을 보존한 채 당일 운동만 바뀝니다.
4. **인바디 비교:** 비교 목록에서 0~6개를 선택합니다. 수치별로 서로 다른 날짜의 유효한 값이 2개 이상일 때 실제 측정 간격과 변화량을 표시합니다. 같은 날짜에 여러 측정을 선택하면 그 날짜는 변화량 계산에서 제외합니다. 미입력 수치는 추정하지 않으며 사진은 전송하지 않습니다.
5. **수행 기록으로 조정:** 조정할 저장 계획을 `보기`로 열고 현재 조건을 확인합니다. `실제 수행 기록으로 계획 조정`에서 최근 7일/28일과 어려웠던 점을 선택·입력한 뒤 전송 미리보기를 확인하고 `열린 계획을 수행 기록으로 조정`을 누릅니다. 현재 조건과 원본 계획의 프로필·ID, 기간 내 기록을 함께 사용하고 기록 없는 날짜는 실패가 아닌 미확인으로 구분합니다. 결과와 변경 이유를 검토한 뒤 필요할 때 다시 루틴에 적용합니다.

지난 세트 비교는 저장 당시 운동 이름이 같은 기록을 기준으로 합니다. 다른 단위나 자유문자 입력을 임의로 합산하지 않습니다. 계획 조정에는 최근 수행 기록 최대 56개와 실제 세트 상세 총 80개를 보내며 생략 수를 표시합니다. 자동 증량, 자동 계획 적용, 의료 진단은 제공하지 않습니다.

### 기존 OAuth 설치 재사용

- 참조 프로젝트 `F:\06_DavValult\REEDO_StockImage\ima2-gen-reedo`에 설치된 `openai-oauth` 실행 파일을 재사용합니다. 참조 프로젝트 코드나 패키지는 수정하지 않습니다.
- FitMind 웹 서버 기본 포트는 **8787**, 필요할 때 시작하는 FitMind 소유 OAuth 프록시 기본 포트는 **10541**입니다. 참조 앱의 기존 10531 프로세스를 중단하지 않습니다.
- OAuth 프록시는 기존 Codex 인증 파일을 사용합니다. 토큰을 FitMind 코드·브라우저·LocalStorage·백업에 복사하지 않습니다. 인증 파일 갱신은 기존 프록시가 담당합니다.
- Windows에서는 설치된 Codex 앱의 CLI 실행 파일을 찾습니다. 다른 설치 경로는 `FITMIND_CODEX_BIN`으로 지정할 수 있습니다. 패키지를 자동 설치하거나 `npx`로 다운로드하지 않습니다.
- 별도 OpenAI API 키 입력은 없습니다. 요청에는 연결 계정의 Codex 사용량과 모델 접근 제한이 적용됩니다. 개발 도구의 로그인 화면만 보고 연결 성공으로 판단하지 않고 실제 모델 목록 응답을 확인합니다.
- OAuth 프로토콜은 참조 앱의 `/v1/responses` 스트림을 사용합니다. 완성된 출력 항목과 최종 완료 신호를 함께 확인하여 설치 프록시의 응답 합치기 과정에서 본문이 사라지는 문제를 처리합니다.

환경이 다를 때만 실행 전 설정하세요.

```powershell
# 참조 프로젝트 위치가 달라진 경우
$env:FITMIND_REFERENCE_ROOT = 'D:\projects\ima2-gen-reedo'
# 이미 실행 중인 로컬 OAuth 프록시를 재사용하는 경우
$env:FITMIND_OAUTH_URL = 'http://127.0.0.1:10531'
# 설치된 Codex 실행 파일을 자동으로 찾지 못하는 경우
$env:FITMIND_CODEX_BIN = 'C:\path\to\codex.exe'
npm start
```

`FITMIND_PORT`로 웹 서버 포트도 바꿀 수 있지만, 포트가 바뀌면 브라우저 저장 공간도 달라집니다. OAuth URL은 HTTP loopback 주소만 허용합니다. 원격 Vercel 정적 배포나 `file://`에서 로컬 인증을 직접 사용하지 않습니다.

### 데이터와 실패 처리

- 추천 버튼을 누를 때 프로필·상세 목표·비교 목록에서 선택한 인바디 수치와 메모를 OpenAI로 전송합니다. 계획 조정 요청에는 화면에서 확인한 원본 계획과 최근 수행 기록·실제 세트·어려웠던 점도 포함합니다. 인바디 사진은 전송하거나 자동 판독하지 않습니다.
- 누락 수치를 추정하지 않도록 요청하고, 결과의 JSON 구조·요일·세트·시간 예산을 검증합니다. 이 검증이 의료적 적합성을 보증하지는 않습니다.
- 요청은 자동 재시도하지 않습니다. 인증 만료, 사용량 제한, 시간초과, 잘린 응답, 잘못된 계획은 실패로 안내하며 기존 계획을 보존합니다.
- `응답 대기 중지`는 브라우저의 대기를 끝냅니다. 기존 프록시가 실제 생성을 중단하지 않을 수 있어 이전 요청 종료까지 중복 요청을 막습니다. 시간초과 후에도 잠시 대기한 뒤 연결 새로고침으로 상태를 확인하세요.
- 저장공간이 부족하면 결과를 저장했다고 표시하지 않습니다. 전체 데이터 백업으로 먼저 보관할 수 있습니다.
- 모델 선택·추가 목표·인바디 선택은 기존 로컬 상태에 보관되고 백업/복원에도 포함됩니다.
- 다른 탭이 저장 데이터를 변경하면 오래된 탭의 쓰기를 중단하고 안내합니다. 미저장 기록은 전체 데이터 백업으로 보관한 뒤 다른 탭을 닫고 새로고침하세요. 자동 병합이나 원자적 동시 쓰기 잠금은 제공하지 않습니다.

공식 Codex 로그인 방식과 인증 저장 동작은 [OpenAI 인증 문서](https://learn.chatgpt.com/docs/auth)를 참고하세요. `openai-oauth`는 참조 프로젝트에 이미 설치된 별도 브리지이며 공식 Codex 자체와 구분됩니다.

## Vercel 자동 배포

GitHub `MetachainArt/FitMind-AI`의 `main` 브랜치에 푸시하면 연결된 Vercel Production 배포가 실행됩니다. 공개 주소는 [FitMind](https://fitmind-ai-eight.vercel.app)입니다.

`npm run build`는 브라우저에 필요한 HTML·CSS·JavaScript 6개만 `dist/`에 복사합니다. Vercel은 이 폴더만 공개하며 로컬 OAuth 서버·테스트·검증 문서는 웹 배포에 포함하지 않습니다. GPT 추천·조정은 위의 로컬 실행 방법을 사용하세요.

## 검사

```powershell
npm run check
```

JavaScript 문법 검사와 기존 스모크, 진단 회귀, AI 클라이언트, 가상 OAuth 서버 통합 테스트를 실행합니다. 자동 검사에는 실제 AI 호출이 없습니다. 실행 중인 앱에서 추천 버튼을 누르면 실제 계정 요청이 발생합니다.

새 프로덕션 의존성 없이 루틴 적용·수행 기록·계획 조정 기능을 추가했습니다. 사용 방법과 검증 범위는 [2026-09-21 기능 구현 기록](docs/audit/2026-09-21-workflow-features.md)을 참고하세요.

진단 보고서의 BUG-001~011을 수정했습니다. 실패한 백업 복원의 데이터 보존, 초기화, 인바디 결측값·이미지 저장 실패, 추가 세트 재개, 장비/시간 제약, 실제 측정 간격, 세션 시작일, 완료 타이머 종료 및 저장 읽기 실패를 회귀 검사합니다. 기존 보고서는 진단 당시의 기록으로 보존합니다.
